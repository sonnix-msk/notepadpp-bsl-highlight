# 1. Infostart (инструмент + статья)

**Название:** Нормальная подсветка кода 1С (BSL) в Notepad++

**Кратко (лид):**
Подсветка синтаксиса языка 1С:Предприятие для Notepad++ на базе грамматики tree-sitter —
не «пользовательский язык», а настоящий разбор кода. Ставится двойным кликом, работает в
64- и 32-разрядном Notepad++ 8.x.

**Текст:**

Notepad++ удобен для быстрых правок, но нормальной подсветки 1С в нём не было. То, что
продаётся под видом «языка 1С», — это User Defined Language: наборы слов без регулярных
выражений и без контекста. Готовые UDL бедные (десятки слов) и не поддерживаются. Импортировать
грамматику из VS Code или другого редактора нельзя — там другой движок.

Решение — на базе tree-sitter (так же устроена подсветка в VS Code, Neovim, Zed). Для языка
1С грамматика уже написана; я собрал её под Notepad++ и настроил правила раскраски.

Что подсвечивается:
- ключевые слова, строки, числа, даты, комментарии, операторы, идентификаторы;
- директивы препроцессора целиком и в одну строку — `#Область Имя`, `#Если Клиент Тогда`,
  `#КонецЕсли`, `&НаСервере`;
- фолдинг процедур/функций/блоков;
- файлы `.bsl` и `.os`.

Скачать и исходники: <ссылка на релиз>.

# 2. Хабр (техническая статья)

**Заголовок:**
Подсветка 1С в Notepad++ на tree-sitter: от нуля до релиза (и что из этого сделал AI-ассистент)

**Лид:**
Хочу нормальную подсветку BSL в Notepad++. Стандартный путь — «пользовательский язык» —
упирается в потолок: в нём нет ни регулярных выражений, ни контекста. Разбираю, как сделать
по-настоящему (tree-sitter), и честно показываю, где работу делал я, а где — AI-ассистент.

## Проблема: почему UDL бессилен

- UDL в Notepad++ — плоский токенизатор: 8 списков слов + операторы. Regex нет, контекста нет.
- Грамматики из VS Code (TextMate), JetBrains, Vim в UDL **не импортируются** — разный движок
  (`begin/end`, `include`, lookbehind в UDL отсутствуют как класс).
- Готовые UDL для 1С — десятки слов, брошены.

## Идея: tree-sitter

- tree-sitter строит синтаксическое дерево и красит токены по роли. Для BSL грамматика уже
  есть (`alkoleft/tree-sitter-bsl`), а для Notepad++ — плагин-хост `Thorium/NppTreeSitter`,
  умеющий грузить грамматики как «настоящие» языки.
- Что оказалось тупиком: LSP-клиент `NppLspClient` + `bsl-language-server` **подсветку не даёт** —
  обработчики semantic tokens в нём заглушки `// TODO` (проверено в исходниках).

## Сборка грамматики

- Из `parser.c` собираем `tree-sitter-bsl.dll` через MSVC (Build Tools), грузим в папку плагина.
- **ABI:** грамматика собрана tree-sitter 0.25 → ABI 15. Проверили, что рантайм плагина ABI 15
  принимает — пробингом его же бандловых грамматик (`python`/`rust`/`go` = 15).

## Правила раскраски и неочевидное

- Написали `bsl-highlights.scm` (tree-sitter query), цвета — в `TreeSitterLexer.xml`.
- **Приоритет правил:** плагин рисует совпадения по `(позиция, номер паттерна)`, побеждает
  **последнее**. Выяснилось чтением C++ плагина, не документации. Общие правила — в начало,
  частные — в конец.
- **Многострочная нода `preprocessor`.** Директива однострочная, но нода оборачивает весь блок
  `#Если…#КонецЕсли`. Красить ноду нельзя → красим её прямых детей (`#Область`, `Тогда`,
  `expression`-условие), тело не задеваем.

## Установщик для «непрограммиста»

- `INSTALL.bat` + PowerShell: ищет Notepad++ (реестр → типовые пути → ручной ввод), определяет
  разрядность по PE-заголовку, поднимает UAC, бэкапит конфиг. Пакет — x64 + x86.
- Грабли дистрибуции: имена файлов латиницей (иначе cp866-кракозябры в zip), `.ps1` в UTF-8 с BOM.

## Неожиданное: антивирус

- Касперский пометил `tree-sitter-bsl.dll` как `not-a-virus:...RiskTool...BitCoinMiner.gen`.
  Ложное срабатывание: маленькая неподписанная DLL без метаданных. Внутри — таблицы разбора,
  ни строк майнера, ни сетевых API, энтропия обычная.
- Лечение: добавили **VERSIONINFO** (имя, версия, назначение), пересобрали. Плюс помогло
  понимание, что антивирусы кешируют по хешу.

## Воспроизводимая сборка

- Сначала DLL «плавала» (MSVC вшивает метку времени и пути). Решение — `/Brepro /d1nodatetime`
  (cl) + `/link /Brepro`. Проверили: два прогона и сборка из разных каталогов дают **один SHA256**.
  Это и защита от подмены, и ответ на «а точно не вирус?».

## Что не стали делать (и почему)

- Подсветка языка запросов 1С внутри строковых литералов. Грамматика запросов есть (`sdbl`),
  инъекции плагин поддерживает. Но: (1) плагин **игнорирует `#match?` при сборе инъекций**
  (проверено в исходниках — `EvaluatePredicates` там не вызывается), значит под краситель
  попали бы все строки; (2) нет поддержки конкатенации (`"ВЫБРАТЬ …" + ИмяТаблицы + …`), а в 1С
  это частый случай. Честный вывод: не тот инструмент, отложено.

## Роль AI-ассистента (честно)

Где ассистент реально помог: чтение исходников плагина (нашёл приоритеты и баг с инъекциями),
разбор ABI, диагностика FP антивируса, воспроизводимость сборки, рутина установщика и оформления.
Где решения были мои: что вообще делать, какие каналы, что **не** реализовывать, отбор находок.
